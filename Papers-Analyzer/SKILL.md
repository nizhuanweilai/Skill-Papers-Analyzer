# Papers-Analyzer

把论文 PDF 变成一张结构化 Excel 表格：一篇论文一行，每一格都**必须能在论文原文中找到出处**。

本技能最核心的价值是“可信”：表格是给人做综述、做汇报、做对比用的，一旦混入编造的信息，整张表就失去意义。所以下面所有规则都围绕一个原则——**宁缺毋假**：论文里找不到的信息就留空，不硬凑、不脑补、不猜。

## 适用范围

- 输入：一个或多个论文 PDF 文件（本地路径），或可直接下载的 PDF 链接（期刊官网、arXiv 等）。多篇论文时，**每篇论文一行**，汇总到同一个 Excel。
- 输出：一个 `.xlsx` 文件，固定 15 列、中英双语两行表头（见下文“输出表格结构”）。
- 不支持：从论文中提取模型架构的**原图**。架构图请用户自己从论文截图，本技能只输出架构的**文字描述**（在交付说明里提醒用户这一点）。

## 核心原则（每条都重要）

1. **只填论文里有的**：每个单元格的内容必须能在论文中找到具体出处（某节、某段、某图注、某脚注）。无法定位到出处的内容一律不填。
2. **不强行凑数量**：论文只讲了 1 个创新点，就写 1 条；没有未来方向，就留空。不要为了“看起来完整”而编造第 2、3 条。
3. **URL 类字段以论文原文为准**：开源代码列只填论文明确给出的 URL（正文、脚注或作者注里白纸黑字写了 `https://...` 才填；只写“代码可应要求提供”而没有 URL 的，留空）。数据集列优先填论文明确列出的数据集名称（见第 12 列规则）。
4. **保留原文专有信息**：论文标题、发表期刊/会议名、代码与数据集 URL、数据集/模型/方法专有名词**始终保留论文原文，不翻译**。分析类内容（研究目标、动机、创新点、优缺点、结构、架构描述、未来方向）的语言跟随用户提问——见“输出语言”一节。
5. **多篇论文时严格“一行一篇”**：不要合并、不要截断、不要张冠李戴。
6. **输出只写分析结论，不写思考过程**：单元格里放整理好的结论，不要出现给自己的提问、待办（如“需补充文献”“为什么这么定义”）这类工作笔记。

## 输出表格结构

固定 15 列，表头占两行（第 1 行中文、第 2 行英文），数据从第 3 行开始：

| 列 | 中文表头（第1行） | English Header（第2行） |
|---|---|---|
| 1 | 论文标题 | Paper Title |
| 2 | 发表年份 | Year |
| 3 | 发表期刊 | Venue (Journal/Conference) |
| 4 | 链接 | Link |
| 5 | 研究目标 | Research Objectives |
| 6 | 研究动机 | Motivations |
| 7 | 创新点及其提出原因 | Key Innovations and Why |
| 8 | 方法优缺点分析 | Method: Pros & Cons |
| 9 | 文章结构 | Article Structure |
| 10 | 模型架构 | Model Architecture |
| 11 | 模型图 | Model Diagram |
| 12 | 开源代码 | Open Source Code |
| 13 | 数据集链接 | Dataset Link |
| 14 | 未来发展方向 | Future Development Directions |
| 15 | 基于本文可提出的创新点 | Proposed Innovations Based on This Paper |

第 14、15 列的分工：

- **第 14 列 未来发展方向**：顺着论文自身方法可自然续写的方向——优先摘录 Conclusion / Future Work 中作者自己提出的方向；作者没写时，写从论文方法可直接延伸的下一步。
- **第 15 列 基于本文可提出的创新点**：基于论文明确陈述的局限，提出跨范式或跨任务的构想（例如把本文模块与另一技术路线结合、迁移到别的任务）。这一列是“分析者提出”的内容，必须严格基于论文已承认的局限，不能天马行空；论文没有相关局限时留空。
- **第 11 列 模型图**：本技能不提取论文里的架构原图，该列**留空**，供用户自行把从论文截图的模型图粘贴进来。

## 输出语言

- **表头永远双语两行**（第 1 行中文、第 2 行英文），无论用户用什么语言提问；
- **分析类单元格的语言跟随用户**：中文提问则单元格写中文，英文提问则写英文；
- 论文标题、期刊名、URL、方法/数据集名等专有信息始终保留论文原文；
- 文件名：中文提问 `论文信息表_YYYYMMDD.xlsx`，英文提问 `paper_info_table_YYYYMMDD.xlsx`；
- 用户混用语言时跟随任务指令的主要语言，确实判断不了就先问一句。

## 工作流程

### Step 1 读取论文

1. 拿到论文 PDF（本地路径或先下载链接指向的 PDF）。
2. 用 `pdfplumber` 或 PyMuPDF（`fitz`）逐页提取文本。注意：
   - 双栏排版论文，按栏阅读顺序提取（通常先左栏后右栏），避免跨栏错乱；
   - 优先利用章节标题定位内容区域（Abstract / Introduction / Related Work / Method / Experiments / Conclusion / References）；
   - 若 PDF 无文本层（扫描版），告知用户需要先 OCR，本技能不负责 OCR。
3. 对每篇论文，先通读 Abstract、Introduction、Conclusion 建立整体认知，再回到各章节为每个字段取证。

### Step 2 按 15 列逐列提取与撰写

每列写清楚“去哪里找、怎么写”。写法约定是为了让多篇论文的表横向可比，请严格照用。

| 列 | 提取与撰写要点 |
|---|---|
| 1 论文标题 | 首页标题原文，保留原语言与大小写。 |
| 2 发表年份 | 论文首页刊出的年份（期刊卷期、页眉页脚、DOI 元数据均可）；只有 online first 无年份则留空。 |
| 3 发表期刊 | 论文首页刊出的期刊名/会议名原文（如 *Nature Communications*、NeurIPS、AAAI）；arXiv 预印本无期刊/会议信息则留空，不要臆测“将投某刊”。 |
| 4 链接 | 论文本身的链接：用户提供 PDF 时给的论文 URL、论文首页标注的出版方/DOI 链接、或正文标注的 arXiv 编号（如 `arXiv:2511.23260`）——标注编号时构造标准链接 `https://arxiv.org/abs/2511.23260`。只填 URL 本身；正文未给出任何论文链接时留空。生成 Excel 时该列每个有值的单元格必须设为**可点击超链接**（`cell.hyperlink = url`）。 |
| 5 研究目标 | 1–2 句总述论文要做什么；再按主题分条（每条一个主题句 + 1–2 句说明），概括论文的主要研究内容。对应 Abstract 与 Introduction 结尾的 “In this paper, we propose…”。 |
| 6 研究动机 | 先用一两句给出整体研究空白（现有做法是什么、为什么不够）；再分条列 `Motivation#1`、`Motivation#2`…，每条说清“现有做法的局限 + 为什么这是个问题”。形成链条：现有做法 → 缺陷 → 为什么重要。不要写成流水账。 |
| 7 创新点及其提出原因 | 每条创新点用编号标记（如 `a1.`、`a2.`，同篇内连续编号）：先一句标题概括该创新点，再一两句说做法，最后用 `Why：1.… 2.…` 说明提出原因（即针对哪个局限）。若论文只描述了做法没给原因，写做法本身即可，不要替作者编理由。 |
| 8 方法优缺点分析 | 格式固定：先 `优点：` 后编号列出（来自论文明确表述或实验直接支持的强项）；再 `缺点：` 后编号列出（来自 Limitations/Discussion 节作者承认的限制，或论文明确交代的前提条件）。论文没讨论局限就只写优点，缺点留空，不要推测。 |
| 9 文章结构 | 按论文真实章节列出，每章一行：`1. 引言：该章做什么；2. 相关工作：…；3. 方法：…；4. 实验：…；5. 结论。` 每章冒号后一句话概括内容。 |
| 10 模型架构 | 用文字描述：先一句总述（如“整体架构包含四部分”），再编号列出各组件（名称 + 职责 + 数据流向）。**不提取架构原图**（用户自行截图）。论文没有明确架构描述时留空。 |
| 11 模型图 | **整列留空**：本技能不提取架构原图，这一列是预留给用户自己粘贴从论文截图的模型图的位置。 |
| 12 开源代码 | 仅当论文明确给出代码仓库 URL 时填写（如作者注 “Code is available at https://github.com/...”），只填 URL 本身；生成时同样设为可点击超链接；未给出则留空。 |
| 13 数据集链接 | 把论文实验中用到的数据集按论文原文名称列成一行（如 “ETTh1, ETTh2, ETTm1, Electricity, Weather, Traffic”）。论文若给出某数据集的直接下载 URL，可在名称后附上；论文只给名称时就只列名称，**不加“论文未提供下载链接”之类的注释**；两者皆无则留空。 |
| 14 未来发展方向 | 摘录或顺承论文方法的自然延伸方向，每条一句话；优先作者 Conclusion/Future Work 里的原话改写。 |
| 15 基于本文可提出的创新点 | 基于论文明确承认的局限，提出跨范式/跨任务的构想，每条一句话；无明确局限依据则留空。 |

### Step 3 生成 Excel

用 `openpyxl` 写一次性脚本生成 `.xlsx`，格式约定：

- 第 1 行中文表头、第 2 行英文表头，两行都加粗、浅灰填充、**水平+垂直居中**；
- **头两行行高固定为 20**（`ws.row_dimensions[1].height = 20`、`ws.row_dimensions[2].height = 20`）；
- 冻结前两行（`freeze_panes = "A3"`）；
- 每篇论文一行，论文顺序与用户提供顺序一致；
- 所有数据单元格自动换行（`wrap_text=True`）、垂直居顶；
- **列宽固定值**：第 2 列「发表年份」= 10、第 3 列「发表期刊」= 30、第 11 列「模型图」= 80、第 14 列「未来发展方向」= 40、第 15 列「基于本文可提出的创新点」= 40（openpyxl 按列字母设置：B=10、C=30、K=80、N=40、O=40）；其余列（链接/代码等短列、目标/动机/创新点/架构等长列）按内容长短自行取宽，让 15 列可横向浏览；
- **第 2 列「发表年份」和第 3 列「发表期刊」的数据单元格水平居中**（`alignment = Alignment(horizontal="center", vertical="top", wrap_text=True)`），其余数据列保持默认左对齐+垂直居顶；
- **第 4 列「链接」和第 12 列「开源代码」中每个有值的单元格设为可点击超链接**：`cell.hyperlink = cell.value`（openpyxl 默认会渲染为蓝色下划线样式，无需额外设置颜色）；
- 工作表名：中文提问“论文信息”，英文提问 “Paper Info”；
- 文件名：中文提问 `论文信息表_YYYYMMDD.xlsx`，英文提问 `paper_info_table_YYYYMMDD.xlsx`；
- **字体**：所有单元格中西文部分（英文、数字、URL）用 Times New Roman，中文部分用宋体。实现方式：openpyxl 统一 `Font(name="Times New Roman")` 写所有单元格；保存后再后处理压缩包内的 `xl/theme/theme1.xml`，把 `majorFont` 和 `minorFont` 的 `<a:latin typeface="..."/>` 固定为 `Times New Roman`、`<a:ea typeface="..."/>` 固定为 `宋体`；
- **不要标红、不要任何字体颜色强调**：参考样表里的红色标注是人工笔记，不属于输出。所有正文一律自动黑色（不设置 font color），表头加粗即可，不额外上色；
- 保存位置：用户指定路径或源 PDF 所在目录，无法确定时询问；
- 不要图片、不要合并单元格、不要多余工作表。

**单元格写法示例（创新点列，中文形态）**

```
a1. 从标量回归建模直接到概率分布建模
摒弃直接输出单个标量值或预设分布参数（如高斯分布的均值和方差）的做法，将预测重构为直接构建离散概率分布的任务。
Why：1. 无需预设分布形式；2. 可输出置信区间，量化预测不确定性。

a2. 交错双分支结构设计
两个分支使用相互错开的支持集，分支间用一致性损失互为自监督信号。
Why：1. 消除单分支边界量化误差；2. 提升鲁棒性、防止过拟合。
```

**优缺点列示例**

```
优点：
1. 插件式设计，可无缝集成到主流骨干模型；
2. 显式建模全局信息，数据污染场景下平均提升 12.5%。
缺点：
1. 引入 Transformer 时间戳建模，计算开销较大；
2. 依赖时间戳质量，信息量不足时收益有限。
```

### Step 4 交付前自检（逐篇、逐格）

生成后逐格回读：

- [ ] 每个已填单元格都能在论文原文中找到出处（节/段/图注/脚注）；
- [ ] 没有编造的年份、期刊名、URL、贡献点、结论；
- [ ] 找不到信息的字段确实留空，没有用“无/N/A/暂无”占位；
- [ ] 第 14、15 列分工正确：14 列是顺着论文方法的延伸，15 列是基于局限的跨范式构想；
- [ ] 第 11 列「模型图」整列留空（供用户后续粘贴截图）；
- [ ] 第 4 列和第 12 列的 URL 单元格都已设为可点击超链接；
- [ ] 头两行行高为 20、表头居中；
- [ ] 列宽符合约定：年份 10、期刊 30、模型图 80、未来方向 40、可提出创新点 40；年份/期刊数据单元格水平居中；
- [ ] 单元格里没有思考过程、自问自答、待办笔记；
- [ ] 表头是双语两行，数据从第 3 行开始，多篇论文行数与顺序正确；
- [ ] 字体为西文 Times New Roman、中文宋体；全文无标红、无彩色字体。

## 交付说明

用**用户的语言**（中文提问则中文说明，英文提问则英文说明），一两句：

1. 共处理几篇论文、文件名；
2. 哪些字段因论文未提供而留空；
3. 架构原图需用户自行从论文截图，表中仅为文字描述。

## 常见问题

- **论文给了代码/数据地址但被截断**：以论文正文实际出现的完整 URL 为准，明显截断（如 `github.com/xxx` 无仓库名）时留空。
- **同一字段在论文多处说法略有出入**：以最完整、最明确的表述为准，不叠加矛盾说法。
- **拿到的是 arXiv 预印本**：年份以首页会议/期刊年份或 arXiv 提交年份为准；无期刊/会议信息则留空。
- **数据集下载地址藏在附录脚注里**：只要论文明确给出 URL 就算“论文提供”，可附在数据集名称后。
- **一次给 10+ 篇论文**：仍逐篇处理、一行一篇；规模过大时与用户确认是否分批交付。
